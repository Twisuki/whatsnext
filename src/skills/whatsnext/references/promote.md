# promote - 沉淀可复用经验

把一条在任务里验证过的经验, 提升成 `.whatsnext/knowledge/` 下自包含, 可复用的项目经验. 发现 / 使用经验见 SKILL.md "经验发现"; promote 只管**提升这一个写动作**.

## 1. 判门槛(缺一不提升)

- **已验证**: 被当前证据证实, 不是猜想或一次侥幸.
- **可复用**: 另一个独立任务可能受益(不必已发生第二次, "可能复用"即可).
- **能自包含**: 能重写成脱离原任务也读得懂的正向指导.

三条缺一条, 就留在产出它的任务里, 不提升. 失败尝试, 未决研究, 临时 workaround 一律不提升.

## 2. 重写成自包含

提升不是把任务片段搬过去, 是重写:

- 写清**持久结论**(怎么做, 为什么), **应用上下文**(什么场景适用), 需要时给**简短示例 / 步骤**.
- 源链接只辅助考古, 不能是唯一解释——读者不该为看懂它去翻原任务.
- 只留**正向指导**, 剥掉进度 / 排查过程 / 情绪 / 时间线.

## 3. 落位

- 路径 `.whatsnext/knowledge/<title>.md`, 扁平不分层, 一文件一条可独立应用的实践.
- 写 frontmatter 四字段(`title` / `label` / `tags` / `description`, 规范见 [knowledge.md](knowledge.md)): `label` 单值分类, `tags` 用自然搜索词, `description` 点明适用场景——这三样供未来发现时比对相关性.
- parts 能独立选用 / 修改就拆成多个文件; 必须整体理解才合在一起. 主题有机生长, 不预设固定分类法.

## 4. 维护

- 被现实推翻的经验**重写或删除**. 计划区不碰 git, 无版本历史兜底——删除即永久, 删前确认确实过时.
- 不加 stale / revision / recheck 之类元数据, 也不建索引台账. 过时就地改, 不留陈旧标记.

## 边界

- **私有脱敏**: 提升借鉴自其他仓库 / 项目的经验时, 用中性代称(如"参考项目 A"), 只留结论所需的可移植事实, 去掉仓库名 / 路径 / URL / 私有术语. 除非用户明确要求保留.
- **不碰 git**: 写 knowledge 绝不 add / commit / push, 除非用户明确要求.
- **不是记忆库**: knowledge 是项目操作手册, 不承载任务历史, 架构权威, 术语表, 强制规则; 那些留在任务或代码里.
