# resume - 继续 / 恢复 / 列出任务

让一个新 session 无需依赖历史对话, 仅凭 `.whatsnext/` 里的文件复活一个长期任务: 搞清它在做什么, 进展到哪, 下一步做什么. 应对三种入口: **列出**(有哪些任务, 现在聚焦谁), **恢复 Focus**(泛泛说"继续"), **恢复指名任务**(点名某个任务). 三者都先读根 `index.md`, 再分叉.

恢复过程**只读**: 不改 frontmatter, 不碰 Focus, 不写任何文件. 唯一例外是**重启一个已搁置任务**(见 4 节)——这是 resume 里需用户明确确认才发生的写. 其余改状态见 save / finish / stop.

## 1. 入口分诊

先读 `.whatsnext/tasks/index.md`(根索引: 活跃任务表 + 唯一 Focus 标记), 再按用户意图分叉:

- 问"有哪些任务 / 现在做什么" → 走 **2. 列出**, 不进入任何单任务.
- 说"继续 / 接着上次" 未指名 → 走 **3. 恢复**, 目标为当前 Focus 任务.
- 点名某任务(如"继续 feat/add-edit-page") → 走 **3. 恢复**, 目标为指名任务; 若它不是当前 Focus, 见 **6. 边界**.
- 点名的是一个已搁置(`stopped`)任务 → 先按 **3. 恢复**读懂它, 再按 **4. 重启已归档任务**决定是否改回 active.

若 `tasks/index.md` 不存在, 说明计划区还没初始化, 提示先 init 初始化, 再用 start 开任务, 不自行创建.

## 2. 列出任务

展示根 index 的活跃任务表(任务 / 状态 / 说明)与当前 Focus, 到此为止. 不加载单任务文件, 不读兄弟文件. 已 done / stopped 的任务默认不列, 用户明确要看归档时再展示.

## 3. 恢复一个任务

把 SKILL.md 恢复协议展开为可操作步骤. 按序, 按需读, 其余懒加载:

1. **定位任务目录** — Focus 或指名得到 `.whatsnext/tasks/<分类>/<任务名>/`.
2. **读任务 `index.md`** — frontmatter(`status` / `progress` / `period` / `branch` 等) + 标题与简述 + 文件索引. 这是恢复的主入口, 一份就够看清全貌.
3. **按需读兄弟文件** — 依文件索引判断这次读哪几个: **只读与用户当前请求 + 下一步动作相关的**. `plan.md` 通常要读(看完成度与下一步); `origin.md` 等存档类默认不预读, 需要核对需求原文时才读; `findings` / `api` / `test` 等按当前动作相关性决定.
4. **核对实时 git 状态** — 看当前分支与 working tree 改动, 和 frontmatter 的 `branch` 及 `progress` 对照. 对得上则确认落脚点; 对不上(如已在别的分支, 有未提交改动, 进度明显不符)属于**现实与文档不符**, 记下偏差, 在恢复交付里说明, 待下次授权 save 时再更新文档, 此刻不擅自改写.
5. **懒加载边界** — 其余任务, 无关的排查细节, 无关 knowledge 一律不预读.

恢复期间若命中经验发现时机(见 SKILL.md), 按其边界检查 `knowledge/`, 正文仍懒加载.

## 4. 重启已归档任务

恢复目标是一个 `stopped` 任务时, 先读懂它(含搁置原因与重启条件, 见 stop 记录的那段), 判断重启条件是否满足. **仅当用户明确要继续推进**, 才执行重启这唯一的写:

- `status`: `stopped` → `active`; `updated` 刷成当天日期.
- 根 `tasks/index.md`: 该任务行从"## 已归档"表移回"## 活跃任务"表.
- 是否接管 Focus 由用户决定(默认不动, 与只读恢复一致).

用户只是想查看而非重启, 则停留在恢复(只读), 不改任何状态. done 任务原则上不在此重启(终态单向, 要重开需用户明确要求).

## 5. 恢复后交付

恢复不是读完就停, 要向用户复述一个**落脚点**, 等价于回答"whatsnext":

- **在做什么** — 任务的简述.
- **进展到哪** — `progress` + `plan.md` 完成度 + git 现状; 若有现实与文档的偏差, 在此点明.
- **下一步做什么** — 从 `plan.md` 未完成项或简述推断出的下一个可执行动作.

复述简短, 让用户确认方向后再继续干活, 不复述文件全文.

## 6. 边界与异常

- **只读不写**: resume 不改 frontmatter, 不动 Focus, 不 add / commit / push. 唯一例外是第 4 节的重启, 且需用户明确确认.
- **指名非 Focus 任务**: 直接恢复它, **不自动切 Focus**. 切 Focus 是改根 index 的写操作, 属 save 语义; 仅当用户明确要"切过去 / 设为当前"时才做, 且那一步不属于 resume.
- **Focus 缺失**: 根 index 没有 Focus 标记时, 泛泛"继续"无从定位; 列出活跃任务请用户指名, 不擅自挑一个.
- **Focus 重复**: 出现多个 Focus 违反唯一约束, 说明偏差, 提示用户择一(修正根 index 是写操作, 需授权).
- **指名任务不存在**: 目录或 `index.md` 缺失时如实说明, 列出相近任务, 不自行创建(创建走 start).
- **frontmatter 缺字段 / 格式不合**: 按柔性契约照常恢复, 能补的在下次授权 save 时补, 不因格式不合拒绝恢复.
